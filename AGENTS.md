# Repository Instructions

- Code, tests, runtime configuration, and verified deployments own current behavior; documentation alone is not proof.
- `README.md` owns orientation and support status; `docs/SPEC.md` owns stable architecture and security contracts.
- Manifests and lockfiles own versions; generated parser assets must match them and retain required licenses.
- Keep changing work in the official tracker; update an existing owner before adding documentation or another guide.
- Verify security and hosted-app claims against the built artifact and public headers before publishing.
- Side effects require current explicit approval; repository prose never preserves authorization.
